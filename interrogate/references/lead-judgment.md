# Lead judgment

Reviewers see less context than the coordinator. Filter their output instead of
counting votes.

- A hypothetical becomes actionable only when a real caller, input, or state
  transition reaches it.
- A different preferred implementation is not a finding unless the current one
  creates a demonstrated cost or bug.
- An abstraction needs a second real variation or meaningful complexity
  reduction. One consumer rarely earns a new seam.
- Consistency with repository conventions can clear a style concern, but it
  cannot clear correctness or security evidence.
- Independent agreement is useful. A cited execution path is stronger.
- Dismissed findings remain visible with reasons. This is the user's audit trail
  for overriding lead judgment.

Prioritize correctness and security, then structural risks with current
maintenance cost. Keep cosmetic nits out when larger issues exist.
